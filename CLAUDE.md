# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Browser voxel explorer + editor (TypeScript, Vite, three.js r186 WebGL2 with custom GLSL3 ShaderMaterials). Successor of `09-density-terrain` in [world-imaginer](https://github.com/MaestreDniel/world-imaginer); nothing is imported or copied wholesale from there.

**Status:** SP0 complete (2026-09-27), SP1 complete (2026-09-28), SP2a complete (2026-09-30, GENERATOR_VERSION 3), SP2b complete (2026-10-02, GENERATOR_VERSION 3), SP3a complete (2026-10-03, GENERATOR_VERSION 3), SP3b complete (2026-10-07, GENERATOR_VERSION 4), SP3c complete (2026-10-09, GENERATOR_VERSION 5). SP3d complete (2026-10-16, GENERATOR_VERSION 5, the world unchanged: editable density and surface rules, inspector and slice viewer). SP3e complete (2026-10-20, GENERATOR_VERSION 5, the default world unchanged, 59 goldens: the draft presets amplified, archipelago and floating islands). SP4 was split into SP4a and SP4b (2026-10-20): SP4a (the world in 3D, loaded once: a start screen, a loading screen and the RD12 world with exact light, greedy meshes, still water, sky, day/night and fog, in Chrome on RegionBatch and in Firefox on RegionMesh) is complete (2026-10-23, GENERATOR_VERSION 5, the world unchanged). SP4b was split into SP4b and SP4c (2026-10-23): SP4b (streaming: the world without an edge) is in progress, then SP4c (the map in the world and live editing), then SP5.

## Source of truth

- `docs/superpowers/specs/2026-09-26-architecture-design.md` is the master spec. Its **Decisions log (D1-D20) is authoritative** and overrides any other text.
- Every sub-project (SP0-SP12, spec §10) runs spec → plan → TDD implementation. SP specs live in `docs/superpowers/specs/YYYY-MM-DD-sp<N>-<topic>-design.md`, plans in `docs/superpowers/plans/`. A deviation from the master spec is made by amending it explicitly.

## Commands

- `npm run dev` / `npm run preview` — http://localhost:5183 (COOP/COEP headers; open via localhost or HTTPS)
- `npm run build` — `typecheck` (three tsconfigs) + `vite build`
- `npm test` — vitest projects `unit`, `arch`, `metrics-fast`, then `integration` (real worker threads, one file at a time); `npm run test:metrics` (quick, CI), `npm run test:metrics:full` (SP exit), `npm run bench`
- `npm run bench:record` — write `test/baselines.json` on the reference machine (per-kernel ratios to a calibration kernel, plus the lattice3/perm512 kill ratio); `npm run bench` gates +30 % per kernel and kill ratio ≤ 1.6, plus the absolute gates (column p50/p95, SP3b's `terrain.real` p50 ≤ 4 ms, SP3d's `slice.vertical128` ≤ 300 ms, `slice.partWorst` ≤ 250 ms and `session.commitMaxTree` ≤ 4 ms p50, SP3e's `terrain.islands` ≤ 4 ms p50 on floating_islands cluster columns, and SP4a's `light.column` p50 ≤ 4 ms / p99 ≤ 8 ms and `mesh.section` p50 ≤ 1.0 ms / p99 ≤ 2.5 ms), which `bench:record` also enforces before writing; `BENCH_EXEMPT=row,…` (names from `BENCH_ROWS`; SP3c) skips those rows' ratio gate in a pre-record run, never the absolute gates or the kill ratio, and `bench:record` ignores it
- `npm run test:accept-thresholds` — rewrite `test/thresholds.lock.json` (needs a spec amendment in the same change; CI checks it)
- `npm run test:goldens` — record and merge goldens (refuses changed goldens without a `GENERATOR_VERSION` bump)
- `npm run test:accept-schema` — rewrite `test/schema-shape.lock.json` (refuses a removed, renamed or re-kinded leaf unless `SCHEMA_VERSION` was bumped with a migration)
- `npm run test:accept-state-ids` — append the states of new block types to `test/stateIds.lock.json` (append-only: refuses a changed id, a removed entry or a new state of a locked type; the commit message says the lock changed)
- `npm run docs:params` — regenerate the README parameter table from the schema
- `npm run docs:review-slices` — write the SP3e review PNG slices of the draft presets (`archipelago-coast`, `amplified-mountain`, `islands-cluster`: 512-block vertical lines along x through each preset's window centre from `src/metrics/sp3eGoldens.ts`; seed 42, each with its preset's params) and a `slices.json` naming the profile into `docs/superpowers/specs/assets/sp3e/<preset>/` through the region harness; the default sites' slices (SP3c: a coast, a lake, a river, a mountain, y 62, a desert, a snowy mountain and a badlands site with their zooms) stay in `assets/sp3c/` (the default world does not change), SP3a's and SP3b's in `assets/sp3a/` and `assets/sp3b/`; the SP3e tuning before/after sets are in `assets/sp3e/tuning/`
- `npx --yes bun@1 test/tools/goldensJsc.ts` — recompute every golden (SP1, SP2a, SP3a, SP3b, SP3c and SP3e) under JavaScriptCore (D20; SP exit evidence); `?selftest=1` does the same in a real module worker in Chrome and Firefox, and `?lab=noise` keeps the SP1 panel
- `/` — the 3D page (SP4a). A bare `/`, or `/#<hash>` alone, shows the minimal start screen: it names the session's seed and profile (from the `?map` hash, else the defaults); "Enter the world" loads that world in the same page and "Open the map" goes to `?map#<hash>`. Any of `?at=x,z`, `?rd=4…16` or `?workers=2…6` skips it (`?renderer` alone does not). The query also takes `y`, `yaw` and `pitch` (degrees; yaw 0 faces −z, 90 faces +x), `renderer=batch|mesh` (forces the section renderer: the probe picks RegionBatch where `WEBGL_multi_draw` exists, Chrome, and RegionMesh where it does not, Firefox) and the capture mode `shot=1` with `time=<hours>` (no HUD and no overlay, the clock fixed at that hour, 08:00 by default). The loading screen shows a panorama from `public/panoramas/manifest.json` (or a neutral gradient), tips and progress, and the world appears in one frame at the reveal. Keys: WASD, Space/Shift up and down, Ctrl sprint, the wheel or `+`/`-` for the speed, T time speed, R load the world around you, H or F1 help and settings, F3 counts, Esc releases the pointer
- `?flight=sp4a` — the measured flight (SP4a spec §9.5): seed 42, RD 12, a 60 s scripted flight through one day; the page sets `window.__wiFlight.result` and offers "Download JSON". `?spike=batch` — the week-1 spike (§1). `?pano=<id>` — one panorama's capture view
- `npm run assets:panoramas [-- --gpu] [-- --skip-build]` — rewrite the six loading-screen panoramas (`public/panoramas/*.webp`, each ≤ 400 KB) and their `manifest.json` through SP4a's own renderer, in the tool's own headless Chrome (SwiftShader, or the system GPU with `--gpu`) on its own `vite preview` (never 5183); rerun it when the look changes
- `npm run measure:chrome -- --route spike|flight [--gpu iris|rtx] [--workers 4] [--probe-only]` — SP4a's GPU cells (§1.2, §9.5; not in CI), written to `docs/superpowers/specs/assets/sp4a/`. **Who runs which cell:** the Chrome cells (spike and flight on the Iris Xe and on the RTX 3060 Mobile, plus the 4-worker flight on the Iris Xe) are an agent's, with this tool: its own headful Chrome, fullscreen at 1920 × 1080 @ 1 on the laptop panel eDP-1, on a quiet machine (it refuses above a 1-minute load of 2; a locked session makes the frame times invalid), touching no other process and none of the user's browsers. The Firefox cells are the user's, by hand in the user's Firefox through the page's "Download JSON"; the controller commits each file under the GPU the user names (Firefox masks the renderer string). **PRIME notes:** Chrome renders on the Iris Xe only under the on-demand profile (`sudo prime-select on-demand`, then log out and in: the user switches it, never an agent); the tool reaches the RTX through the NVIDIA offload variables (`launchEnv`; prime-run is not installed) and ANGLE's Vulkan backend (`--use-angle=vulkan --enable-features=Vulkan,VulkanFromANGLE`; the first flag alone gives no WebGL2), since ANGLE's GL backend fails `eglInitialize` there; Firefox's RTX cells run under the 'nvidia' profile, where Firefox renders on the RTX natively (under on-demand its offload falls back to software rendering). The tool refuses when the probed renderer does not name the expected GPU
- `?map` — the world map (SP2a) and the parameter editor (SP2b): toolbar, parameter panel, spline drawer, biome table and share chart, presets, cut-line cross-section with its Profile | Voxels toggle (SP3a: the real vertical slice of voxels; SP3b: the density terrain, the slice split across the workers; SP3c: the terrain palette's colours and legend, and the hover readout's surface rule id from the `surfaceProbe` worker job), the drawer's Density tab (SP3d: the `density.defs` and `surface.rules` trees with tap mutes, a node form with param refs, a JSON editor with both validation tiers, and the slice viewer — vertical along the cut line or horizontal at y, final density, any node, blocks or rule masks, a 32² draft then 128², up to 3 pinned slices — on the `fieldSlice` and `fieldProbe` worker jobs), global undo/redo (Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y), P toggles the panel
- `?map&perf=edit` — the same page with the SP2b latency hook (`src/ui/map/perfHook.ts`, `globalThis.__wiPerf`): pins the canvas to 1100 × 825 at seed 42, default profile, view (0, 0, 64 bpp)
- `node test/tools/mapLatency.ts [--profile-dir DIR]` — the SP2b §2.8 edit → preview latency runner (not in CI; about 35 min): builds, serves `dist` on its own free port (never 5183), drives its own headless Chrome and writes `docs/superpowers/specs/assets/sp2b/latency-*.json`; `--quick` for a short run
- `node test/tools/uiSmoke.ts [--profile-dir DIR] [--shots DIR]` — the SP2b UI smoke test (not in CI; about 1 min; SP3a adds the Voxels toggle): `?selftest=1`, then every editor driven with real pointer and key input and checked through the DOM and the URL, no console errors; `--shots` also writes the spec §12 screenshots and (SP3b) the Voxels mode on a mountain line, `cross-section-voxels-mountain.png` (SP3c: with the hover readout's surface rule id); SP3d adds eight Density steps (the tab with a cut line, node edit committed by clicking the next row, mute, broken JSON, the Slice/JSON sub-tabs of a narrow tab, horizontal plane, slider drag, browser times) and five `density-*.png` shots, committed to `docs/superpowers/specs/assets/sp3d/`; SP3e adds the `preset profiles` step (archipelago, amplified and floating_islands opened by URL on 1,024-block lines centred on their golden windows from `src/metrics/sp3eGoldens.ts`: the profile select, the Voxels summaries, the ground under an island, the `islandMask` and `biome` map layers around the windows) and five preset shots, `preset-{archipelago,amplified,floating_islands}.png`, `preset-archipelago-map.png` and `preset-floating_islands-islandMask.png`, committed to `docs/superpowers/specs/assets/sp3e/`; SP4a adds the `start`, `world` (`/?rd=4`) and `world-mesh` steps (the parity check: RegionMesh against RegionBatch at one view, at most 1 % of the pixels off by more than 2/255) in a Chrome rendering through SwiftShader, and the shots `start.png`, `world.png` and `world-mesh.png`
- `docker compose up world-imaginer-voxel`
- Each sub-project appends its id to `STARTED_SPS` in `test/harness/sp.ts` in its first commit. Appending changes the lock (`test/thresholds.lock.json`), so run `npm run test:accept-thresholds` and amend the spec in the same change.

## Conventions

- TypeScript strict. Runtime dependency: `three` only. Dev dependencies: `vite`, `typescript`, `vitest`, `@types/three`, `@types/node`.
- Tests are mandatory (vitest): unit, arch and metric tests. Metric thresholds are locked (`test/thresholds.lock.json`); never loosen one without amending the spec. A part may gate on some tiers only (`tiers`; SP3b's T3 gates on full and is recorded on fast and quick), and dropping a tier counts as loosening. Golden changes require a `GENERATOR_VERSION` bump.
- CI runs `check` (build, arch, integration), the `unit` shards (`.github/scripts/unitShards.mjs`: `heavy` and the catch-all `rest`, rebalanced by the job summaries; SP4b), `metrics-fast` and the `metrics-quick` shards (`.github/scripts/metricShards.mjs`; a new metric file lands in the catch-all `rest`) in parallel, gated by `ci-ok` (SP4a adds the `render` shard: `render.metric.ts`, `light.metric.ts` and `g1.metric.ts`, which reads the committed Chrome flight `flight-iris-chrome.json`); a docs-only change (`docs/**`, `*.md`; not the spec asset JSON under `docs/superpowers/specs/assets/`, which a metric may read, as `g1.metric.ts` does) runs build, arch and the unit shards only. Each SP spec states its expected CI wall-time impact, and its exit evidence records the CI run's wall time. Reference: the first parallel run (2026-10-20, at SP3e's end) took 3 min 12 s wall (longest job `check` 170 s), against 13 min 5 s for the last sequential one.
- Layer rules (spec §1) are enforced by arch tests: `core` ← `world` ← `gen` ← L2 (`light`, `mesh`, `sim`, `persist`, `metrics`); `render/` is the only place three is imported and `render/materials/**` the only place GLSL lives; `sound/` is the only place WebAudio is used.
- In `core/`, `world/` and `gen/`: no `Math.random`, `Date.now`, `performance.now` or `console.*`; in `gen/` no `Math.sin/cos/exp/...` (use `core/detMath`) and no exported numeric constants (tunables live in `ParamSchema`).
- No audio files (`.ogg`/`.mp3`/`.wav`) in the repository; sound packs are user-supplied.
- Conventional commits scoped by area: `feat(gen):`, `feat(render):`, `fix(store):`, `test(metrics):`, `docs(spec):`, …
- Determinism (SP1): in `core/noise/**`, `core/spline/**`, `metrics/**`, `world/blocks/**` (SP3a), and for speed in `light/**`, `mesh/**` and `world/store/padded.ts` (SP4a: vitest's bench mode made the un-aliased jobs several times slower), an imported value binding is used only through a top-level `const` alias (vitest turns imports into getters; arch-tested); `core/`, `gen/` and `world/blocks/**` never call `Intl`, `localeCompare`, `toLocale*`, `.normalize(`, `TextEncoder` or `TextDecoder`; `Math.fround` is banned in `core/`, `gen/` and `world/blocks/**`.
- Generator outputs are NaN-free; every golden hasher writes NaN as `0x7FF8000000000000` (`hashF64`). Every validated parameter number goes through `q15`; canonical JSON throws on NaN, ±Infinity and −0.
- A noise leaf's seed name is its path; renaming the path needs `seedName` to keep the same worlds.

## Runtime and deployment

- SharedArrayBuffer needs `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` on the page **and** every worker script, in a secure context (`http://localhost:<port>` or HTTPS; a reverse proxy must terminate TLS and pass the headers through).
- Vercel is linked to the repository root and sets the headers via `vercel.json`. Docker: own `docker-compose.yml`, port 5183, default compose network (no external network). Production: Vercel project `world-imaginer-voxel` (https://world-imaginer-voxel.vercel.app), separate from maestre-web-next.
