## Goal

Make the three draft presets real and selectable: `amplified` (the default ground with taller, rougher mountains), `archipelago` (a sea of islands) and `floating_islands` (clusters of islands floating at y 190-270 over the default ground). Each is an overlay in `PROFILES`: archipelago changes parameters and splines (the 2D map shows it); amplified and floating_islands carry whole `density.defs` and `surface.rules` trees on SP3d's editable DAG, plus, for floating islands, a real `islandMask` column field from a new 2D cluster noise and an islands term in the density. The default world does not change (`GENERATOR_VERSION` 5, the 54 golden keys byte-identical). The drafts are tuned by eye with the user, measured by Z1-Z3 as diagnostics (SP12 stays their gate), checked for exactness and sanity by gated metrics, and pinned by new per-preset goldens.

## Non-goals

- **Island-edge springs:** the decorate SP (SP8b), which the master already gives "springs, lava lakes and island-edge springs feeding settle" (master §10 SP8b) and whose fluid features and settle do not exist yet. SP3e leaves the islands term, `islandMask` and the island-run predicate (§4.1) as the data a spring placement needs (§12).
- **Final tuning and the Z1-Z3 gates:** SP12. SP3e measures Z1-Z3 and records them; their thresholds enter the table with `activeFrom: 'SP12'` (§5.3). Where SP3e's levers cannot reach a Z threshold the user may hand the miss to SP12 (§1.5).
- **The LOD island scan:** SP11 (master §4.14, R6).
- **`cave_heavy`:** SP6 (`readyFrom: 'SP6'`, `src/core/params/profiles.ts:23`).
- **Amplifying the 2D map's offset:** amplified's amplification lives in the density tree, so the 2D map, the ColumnSample's `offset` and `surfaceEst`, the biome picker and B1 see the unamplified offset; the effect shows in the cross-section's Voxels mode, the slices and the 3D view, not in the 2D map (as SP3d's "a tree edit never changes the map", SP3d's points decided by the user, item 2).
- The `continental` profile (master §10 SP12): stays with SP12 (§13 rewords the master's "may move to SP3e").
- How islands look in the renderer (skylight under islands, meshing of detached runs): SP4 (§12).
- A `detail` term on the islands (their surfaces are 8-block trilinear facets): SP12 (§12), unless the user asks for it in the tuning (§1.5).

5. **Island cluster mask, approach B:** `islandMask` (an existing ColumnSample field, always 0 today) is computed in the column stage from a new 2D noise (λ 700) as `m = smoothstep(0.55, 0.8, u)`, u the noise's uniform value through the existing CDF, only when the preset enables it (default off → 0, goldens unchanged); the density tree reads it with `col islandMask`.

## Decisions taken by this spec (for the user's review)

The brief left these open, or the code survey and the review showed the brief's literal text would not work as intended. The recommendation is the text of the section cited; the alternative is stated.
- **D1 Amplified's offset is the identity below 64** (§1.2): `offset' = offset + 0.9·max(0, offset − 64)`, the master's "`64 + 1.9·(offset − 64)` where offset > 64" (master §3.15). The brief's shorthand `64 + 1.9·max(0, offset − 64)` maps every offset ≤ 64 to 64, which would turn every ocean, beach and river into a flat plain at y 64 (`map-density.md` §4). Alternative: the brief's literal form.
- **D2 Amplified's ceiling** (§1.2): the slide knots move to 300-316 as the brief says, and the ceiling term becomes a soft knee `−3·max(0, y − 270)` (today `−2·max(0, y − 296)`). Measured on 1,000 chunk columns of seed 42 (review): land tops p99 289, max 306, 0.25 % of land tops ≥ 300, no solid voxel at y ≥ 316 (also proved, §1.2), overhangs 6.16 %. Alternatives, measured on the same columns: slope 8 from 300 (the draft's choice): p99 305, max 313, 1.90 % of land tops ≥ 300, i.e. a shelf of summits at y 300-313 that holds Z1's p99; slope 2 from 300: 10 of 2,000 columns (0.5 %) keep a solid voxel at y 319 (`map-density.md` §4), tops cut flat by the build limit. The knee at 270 lies below the brief's "300-316" (open point 2).
- **D3 Islands term coefficients** (§3.1, §3.2): the term is written in the brief's form with its coefficients explicit, `20·(NI − c − a·q + k·(m − 1))`, q = ((y − 230)/40)², and this spec sets **a = 3, k = 4, c = 0.9** instead of the brief's a = 0.35, k = 1, c = 0. Measured with the brief's values (`map-density.md` §5): at m = 0 the term is still positive wherever NI > 1 + 0.35q, so islands fill 9.6-17.1 % of the band in **every** column (not only in clusters), and at the band's edges (q = 1) 35-36 % of the voxels are solid, so every cluster has flat floors and ceilings cut at y 190 and 270. With a ≥ clampSigma (3) the term is ≤ 0 at q ≥ 1, so the band window cuts nothing; with k = 4 the term is ≤ 0 wherever m ≤ 0.25, so islands exist only inside clusters. The core offset c: at c = 0 the m ≈ 1 core is one connected floating mass (review, simulated over 256 × 256 blocks: the largest 3D component holds 95.0 % / 99.5 % of the island voxels, footprint 73 % / 80 %, seeds 42 / 7); the bodies only break up for an offset of about 0.8-1.2 (largest component 39-52 %, footprint 14-48 %), so c = 0.9 is the draft value, a tuning lever (§1.5). Alternative: the brief's values with the measured defects accepted for the draft (and SP12 to fix them).
- **D4 Islands term placement and gates** (§3.1, §3.4): inside an `interpolated` node (the term costs ≈ 1 % of the default's static column cost, instead of ≈ 98 % at voxel placement, and keeps `terrain.real` under its gate; `map-density.md` §2, §5), with a `rangeChoice` on `col islandMask` (≥ 0.25) and one on `y` (window [192, 265), the corners 192 … 264, the 10 layers `map-density.md` §5 measured), so columns outside clusters and cells outside the band never sample NI. With c = 0.9 the window and the gate are exact (§3.2). Alternatives: the wider window [184, 273) (exact for every c ≥ 0, +20 % NI corners); voxel placement (exact band, ≈ 10 ms per column).
- **D5 Water under floating islands** (§3.5): with the islands enabled, water v0 fills the sea under an island as everywhere else: a per-position water base (the top of the highest solid run whose bottom is below `ISLAND_RUN_MIN_BOTTOM` 181) replaces the highest solid voxel **only in the fill predicate**; the highest solid voxel still feeds the heightmaps, which stay unchanged. Today the sea under every island over an ocean would be a dry hole to the sea floor (`src/gen/pipeline/terrainStage.ts:82-104`). Off, the code path is today's. Alternative: accept the dry holes in the draft and hand them to SP12.
- **D6 The island predicate uses existing conditions** (§4.1): `yAbove{minY 181, runTop true}` then `stoneDepth{ceiling, offset 100}`. No new condition kind, so no change to `sp3c.surface.ops` (whose test requires the fixture to use every condition kind, `test/unit/goldens.sp3c.test.ts:119-122`), the inspector, the fuzz or the condition table. The predicate contains every island run and some other runs (§4.1). Alternative: a new exact `runBottomAbove` kind (`map-surface.md` §8 option B), with a new golden key for its coverage.
- **D7 Island tops are grass everywhere** (§4.2): the brief's "grass with dirt below by the column's biome" is read as: grass top, `dirt` under it for the position's surface depth, stone underside; the column's biome (the ground's 2D biome, `src/gen/surface/scan.ts:198-205`) shows through SP8a's grass tint, not through other blocks. The ground's biome says nothing about an island 150 blocks above it (an ocean or desert biome would give sand; the lapse rate would give snow at y 190-270 for most temperatures, `map-surface.md` §7), and Z3 asks ≥ 90 % grass tops. Alternative: snow tops for the frozen biomes (≈ 15 % of tops, Z3 ≈ 85 %).
- **D8 Archipelago's C remap reaches every C-keyed default, with a shift of +0.42** (§1.3): one map φ of the C axis (C + 0.42 for C ≥ −0.24) is applied to the offset, sigma and jag splines, `rivers.coastFadeLo/Hi`, `lakes.minC` and the C bounds of the biome boxes, so sigma, jag, valleys, lakes and beaches follow the new shoreline instead of acting in the new shallow sea (`map-params.md` §9 item 7). The shift puts the default's shore (offset0 = 63, between C −0.16 and −0.1) at C 0.26-0.32, so every C_u < 0.2 is ocean, as the brief says. Measured (review, 512² cells at step 64, seeds 1, 2, 42): ocean share 0.645, 0.653, 0.628, the middle of Z2's 60-75 %. Alternatives: +0.3 (the draft: the shore at 0.14-0.2, inside C_u < 0.2; ocean 0.585, 0.592, 0.568, below Z2's floor on every seed); +0.33 (0.600, 0.607, 0.582); only the offset spline remapped (jag up to 55 blocks and σ under the new shallow sea; beaches off the shore).
- **D9 The `islands` group is top-level, last in the schema, and hashed by the `shape` stage** (§2.1): appended after `surface`, so `randomParams` and `randomPatch` (which draw leaf by leaf in schema order, `test/harness/params.ts:91-160`) draw every earlier group as today; `params: ['shape', 'rivers', 'lakes', 'islands']`, so an edit of the mask dirties the map's `islandMask` tiles and the T stage. Alternatives: after `lakes` (the draft: shifts the draws of every later group); `shape.islands` (no registry change, but non-spline leaves in the shape group); under `density.` (terrain-only hash: stale map tiles).
- **D10 `islands.enabled` is a `bool` leaf** (§2.1), the schema's first: the parameter panel gains a checkbox control and U2 a bool perturbation (`map-params.md` §2). It switches the mask and water v0's island rule (D5; and the scan rule if D21 (b) is chosen). Alternative: no switch (the default would then compute a mask and move `sp2a.column.*`), or an int 0/1.
- **D11 The mask's u** (§2.2): `u = toUniform(z2)` ∈ (−1, 1), the climate convention (`src/core/noise/cdf.ts:6-8`, as master §3.15's C_u), at unscaled world block coordinates (as the density and surface noises: `climate.scaleMul` does not zoom the clusters), 2 octaves. With these, m > 0 on ≈ 22.5 % of the area, m ≥ 0.9 on ≈ 12.5 % and m = 1 on ≈ 10 % (measured 21.9 % and 9.7 %, `map-column.md` §2). Alternative: rivers' (u + 1)/2 convention (45 % / 20 %).
- **D12 Preset trees are derived from the default trees in code and registered at load** (§1.1), in a new core module, so `checkJson` returns them as themselves and identity holds across `resolveProfile` calls (`map-params.md` §4). Alternative: literal trees (no derivation; harder to review against the default). A `defs`-based restructuring of the default density (SP3d §13) is not needed: the derivation replaces subtrees and no term is shared between trees.
- **D13 Constants, not leaves:** the preset trees' numbers (0.9, 1.6, the slide knots, the ceiling, 20, 3, 4, 0.9, 230, 0.025, the windows) are tree literals, editable in the Density tab; no new `density.*` number leaves (no schema-shape, U2 or README consequences), and no ref to an upstream group, so SP3d's ref-target widening is not needed. Alternative: leaves under `density.` (ref targets for sliders).
- **D14 Goldens in a new module** (§6): `src/metrics/sp3eGoldens.ts` with `sp3e.*` keys chained last, five keys (three region hashes, and 2D column points for archipelago **and floating_islands**: the latter is the only golden that pins `islandMask`'s values), observed by a new `test/unit/goldens.sp3e.test.ts`. Each region window is found by a pinned search, because the SP3a window near the origin may hold no island or mountain. Alternative: extending `sp3a.region.T.<p>` and `sp2a.column.point.<p>` (moves more pins, among them `goldens.sp3a.test.ts:37`, which uses `sp3a.region.T.amplified` as its unknown key).
- **D15 B1 for amplified and floating_islands is gated by identity** (§5.4): their B1 inputs (climate, shape, rivers, lakes, biomes) equal the default's, so their B1 is the default's, already gated; a part counts presets whose inputs differ. Archipelago gets its own parts, minShare included; if the dry run measures archipelago's minShare below 0.3 % (estimated ≈ 0.24 % with D8's land share of ≈ 36 %, open point 4), the spec goes back to the user.
- **D16 Z1-Z3 as threshold rows with `activeFrom: 'SP12'` and `tiers: ['quick', 'full']`** (§5.3): recorded on every tier and not gated now; they activate when SP12 starts, as master §10's DoD rule says, and then gate on the quick and full tiers only (the fast tier's 64-column samples are too small; the T3 precedent, `test/thresholds.ts:53`). Alternative: unlisted extra values of a gated call (SP12 would then have to add the rows).
- **D17 The bench row runs on cluster columns** (§7): `terrain.islands`, `fillColumnT` on floating_islands at 256 timed columns from the `terrain.real` candidate sequence whose centre has m ≥ 0.5, precomputed outside the timing, gated at p50 ≤ 4 ms. On `terrain.real`'s plain columns ≈ 77.5 % have m = 0 and cost the default, so the p50 would hide the term (`map-density.md` §6).
- **D18 Three harness extractions, parameterised** (§5.1): (1) T1-T5's threaded column scatter and per-column analysis move from `test/metrics/terrain.metric.ts` to `test/harness/terrainScatter.ts`; (2) DT2's per-column checks from `test/metrics/region.metric.ts` to `test/harness/dt2.ts`; (3) S1-S3's threaded analysis from `test/metrics/surface.metric.ts` to `test/harness/surfaceAnalysis.ts`. They are not plain moves: each extracted function takes what is a module constant today (the worker dir, the params, the columns, the stream, the population mode) as an argument (signatures in §5.1), and the existing files call them with today's constants, so their streams, loops and outputs are unchanged, which §5.7 proves. The preset file reuses them without entering the `PROFILES` worst-of aggregation (`map-metrics.md` §2). The top-down heightmap predicate moves from `test/unit/terrainStage.test.ts:316-330` to `test/harness/heightmaps.ts`.
- **D19 The default world's metric outputs are compared exactly** (§5.7, §10), as SP3d's exit did, with the comparison rules of §5.7.
- **D20 The map layer is appended** after `jag` (§2.6), with the other raw ColumnSample-field layers, and the level-256 preview computes the mask too (`sampleCoarse` writes 0 today, `src/gen/column/columnPoint.ts:99`).
- **D21 The ground under an island** (§3.5, §4.5): the default rules' sky-open run is the first run of a position (`reference.ts:199`), so under an island the ground's top run is not sky-open and, with a sky-gated tree, takes the band state (`src/gen/surface/compile.ts:389-391`): bare stone at y ≥ 8 on the ground and the sea floor under every island (a "shadow"; roughly 10 % of the area at c = 0, less with c = 0.9). (a) Accept it for the draft and hand it to SP12 (built as written: no scan change). (b) The ground keeps its palette: with `islands.enabled` the scan's sky-open run is the highest run whose bottom is below 181, and the island branch becomes its own child before the sky-open sequence (§4.5). The spec builds (a); the before set (§1.5) shows its Voxels shot and Z3's measured `shadowDiff`, and the user chooses (open point 1).

## Open points for the user

Each keeps the user's decisions as approved; the spec's recommendation is stated.
1. **The ground under islands (D21).** The brief says "the normal ground stays as default", but with the default rules the ground and sea floor under every island turn to bare stone. The spec builds option (a) (accept, SP12) and specifies (b) (the ground keeps its palette, at the cost of a scan change and of the surface pass's sky gate, §4.5). 2. **Amplified's ceiling knee at y 270 (D2).** The brief moves "the slide knots and the ceiling term" to 300-316. The slide knots are 300-316; the recommended ceiling starts at 270 with slope 3, because the slope-8 ceiling at 300 piles the top 2 % of the land into a shelf at y 300-313. Alternatives in D2.
3. **Z2's "islands ≥ 1 km² per 100 km²" is out of reach of SP3e's levers.** Measured 4.9-6.9 per 100 km² with the draft and at most ≈ 10 with any combination of φ shift, C wavelength (480-1200), C octaves and warp (Z2 wants ≥ 20): thresholding one fBm field makes one large island (53-92 km²) plus hundreds of islets. The spec proposes, at the approval of the before set, to accept the miss and hand it to SP12 with the numbers (§1.5, §12).
4. **Archipelago's B1 minShare.** With D8's land share (≈ 36 %, from ≈ 56 %) the rarest land biome is estimated at ≈ 0.24 %, below B1's 0.3 % floor; the part is not loosened silently, so the dry run is expected to come back with the options of §5.4.

## 1. The presets as overlays

### 1.1 Mechanics

- **Overlays.** Each preset is its `PROFILES` entry (`src/core/params/profiles.ts:17-24`): `resolveProfile(id)` = `applyPatch(SCHEMA, DEFAULTS, overlay)` (`profiles.ts:36-40`). Splines, the box table and `json` leaves are atomic (replaced whole after `checkLeaf`, `src/core/params/kit.ts:450-478`), so an overlay carries whole values. The final overlays:
  - `archipelago: { climate: { C: { wavelength: 840 } }, shape: { offset: ARCHIPELAGO_OFFSET, sigma: ARCHIPELAGO_SIGMA, jag: ARCHIPELAGO_JAG }, rivers: { coastFadeLo: 0.3, coastFadeHi: 0.4 }, lakes: { minC: 0.32 }, biomes: { table: ARCHIPELAGO_BIOME_TABLE } }`;
  - `amplified: { density: { defs: AMPLIFIED_DENSITY_TREE } }`;
  - `floating_islands: { islands: { enabled: true }, density: { defs: FLOATING_DENSITY_TREE }, surface: { rules: FLOATING_SURFACE_RULES } }`.
  `readyFrom` is already `'SP3e'` for all three (`profiles.ts:20-22`); `CURRENT_SP` → 'SP3e' makes them selectable (§11). `PROFILE_IDS` keeps its order (default, large_biomes, archipelago, amplified, floating_islands, cave_heavy, `profiles.ts:14`); every per-preset loop of this spec runs in that order.
- **Registered trees** (D12). `defaultTrees.ts`' private `registeredTree` (`src/core/params/defaultTrees.ts:15-20`) is exported. `presetTrees.ts` builds each preset tree from the default tree by a deep JSON clone and a list of subtree replacements at JSON paths (each path must exist and name the node stated below, else module load throws), then passes the result through `registeredTree`. So `checkJson` returns the tree as itself (`src/core/params/json.ts:112`), `resolveProfile` yields the same identity on every call, the tier-2 memos hit (`src/gen/trees.ts:6-8`), and `diffParams` compares by identity (`kit.ts:487`). An unregistered literal would re-run tier 1 and give a new identity on every session commit (`map-params.md` §4).

### 1.5 Tuning procedure

As SP3b's retune (SP3b §8.4) and the brief:
1. **Before set.** The dry run builds the drafts exactly as specified and produces: the review slices and the Voxels and map shots (§8) at the review lines fixed by the first window search (§6), kept for every later set so before and after compare the same lines; `presets.metric.ts` on the quick tier (Z1-Z3 with their extras, the gated `DT2.presets` and `B1.presets` parts); the `terrain.islands` p50 (§7); the fast tier's wall time of `presets.metric.ts` (§5.1). Expected from the review's measurements: Z1 overhangs ≈ 6.1 % (master ≥ 8 %), p99Top ≈ 289 (≥ 250); Z2 oceanShare ≈ 0.63-0.65 (0.60-0.75), islandsPer100km2 ≈ 7-8 (≥ 20); Z3 unknown (the core's footprint with c = 0.9 is the open measurement); `terrain.islands` ≈ 3.9 ms plus unmeasured terms (§7); minShareArchipelago ≈ 0.24 % (B1 floor 0.3 %).
2. **Targets.** Each Z part aims at the master's threshold where the levers below can reach it. Where they cannot (Z2's islands part has no lever: §1.3), or where the look and a Z value disagree, the user decides at the approval of the set; the choice "accept and hand to SP12" records the measured value, and §12's SP12 note carries it.
3. **Proposals.** Any change is proposed to the user with its "after" set under `assets/sp3e/tuning/` (slices and shots at the same lines, Z1-Z3 next to the master's thresholds, the gated preset parts, the `terrain.islands` p50 and the fast-tier time), produced by a throwaway plan tool as SP3b's (not committed tooling), and lands only with the user's approval. A set that fails a gated part (§5.2, §5.4), the bench gate (§7) or the fast-tier budget (§5.1) is shown with that failure and the options of the section concerned; the user never approves a failing set unknowingly.
4. **Levers** (what may move, with approval): amplified's offset factor 0.9, σ factor 1.6 (Z1's overhangs), jag factor 1.6, slide knots, ceiling knee and slope; archipelago's C wavelength, C octaves and the φ shift s (the table and splines of §1.3 are then rewritten with the new literals); floating_islands' 20, a, k, c (the core's break-up), the band centre and half-width (230, 40) with the window, NI's wavelength, yScale and octaves, the mask's lo and hi, the mask noise's wavelength and octaves, the m gate (0.25), the branch's ceiling offset 100 and underside depth 2, and the islands `detail` term (§12, cost measured if added). `ISLAND_RUN_MIN_BOTTOM` (181) is frozen unless the band moves; it then moves as one constant (water v0, the branch's minY, Z3; §4.1).
5. **Invariants** a proposal keeps, or the proposal states which argument it gives up: the window cuts nothing, c + a·q ≥ cs at the window's lowest and highest corners (§3.2; else the window widens); the gate cuts nothing, gate ≤ 1 − (cs − c)/k; island voxels stay above `ISLAND_RUN_MIN_BOTTOM`; amplified has no solid voxel at y ≥ 316 by §1.2's corner bound; the numbers of §3.2, §3.4, §12 and §13 (the 192-264 band, the 0.25 gate, SP11's scan) are rewritten with the new constants.
6. **What may not move:** the gated thresholds of §5.2 and §5.4, the Z thresholds (the master's), the default world.
7. **Final values.** They are written into this spec (a "Changes made by the implementation-plan dry run" section, as SP3c and SP3d); the bench and `presets.metric.ts` re-run on the approved values and pass; only then are the goldens of §6 recorded: a recorded `sp3e.*` key can only change with a `GENERATOR_VERSION` bump, which would also move `sp1.params` (SP3d §8), so post-approval retunes are forbidden in SP3e.

### 2.2 The mask (`src/gen/column/islands.ts`)

```
islandMaskAt(ctx, x, z):
  p = ctx.params.islands
  if (!p.enabled) return 0                          // the literal +0
  u = toUniform(N.z2(x, z))                         // N: islands.noise, prepared per GenContext; u ∈ [−uMax, uMax] ⊂ (−1, 1)
  if (p.lo < p.hi) { s = detSmoothstep(p.lo, p.hi, u); return s > 1 ? 1 : s }
  return u >= p.lo ? 1 : 0
```
- x, z are world block coordinates as the caller has them, unscaled and unwarped (D11); `N` is fetched with `noiseFor(ctx, 'islands.noise')` and cached in a `WeakMap<GenContext, NormalNoise>` (the rivers pattern, `src/gen/column/rivers.ts:91-97`); `toUniform(z) = detErf(z·√½)` (`src/core/noise/cdf.ts:6-8`); `detSmoothstep` clamps t to [0, 1] and returns t·t·(3 − 2t) (`src/core/detMath.ts:81-85`).
- **lo ≥ hi** is a legal parameter state (no cross-leaf check exists in kit) and is defined as a step at lo (rivers' `fade` guard, `rivers.ts:44-45`); unguarded, lo = hi would give 0/0 = NaN.
- **Range and sign:** t·t is +0 or positive and 3 − 2t ≥ 1, so s is +0 or positive, never −0 or negative; `toUniform` never returns −0 (`detErf` returns `x < 0 ? −r : r`); a subnormal hi − lo gives ±Infinity for t, which the clamp turns into 0 or 1. The explicit `s > 1 ? 1 : s` makes m ≤ 1 by construction. The step returns the literals 1 and 0. So m ∈ {+0} ∪ (0, 1].
- The gen hot-module rules apply (imported bindings aliased as top-level consts, no `Math.*` transcendental; `test/arch/rules/banned.ts:25-26,135-160,197`).
- **Cost** (`map-column.md` §2, measured on 2 octaves): 172 ns per point, 8.4 µs per ColumnSample (49 lattice points), 1.3 % of a 672 µs ColumnSample when enabled; off, one branch per point. The P1 column gate and `column.sample` run on `DEFAULTS` (off) and do not move.

### 3.2 Why these coefficients and windows (D3, D4)

Let cs = NI's clampSigma (3, the default for unspecified fields, `src/core/noise/types.ts:16-24`); NI ∈ [−cs, cs] (`src/core/noise/normal.ts:12`, `:67-72`). Corner y values are −64 + 8k; q at the corners near the band: 184 → 1.3225, 192 → 0.9025, 200 → 0.5625, 256 → 0.4225, 264 → 0.7225, 272 → 1.1025.
- **Clusters only.** BODY ≤ 0 at every corner whose m ≤ 1 − (cs − c)/k (= 0.475 at cs 3, c 0.9, k 4), because BODY ≤ 20·(cs − c + k·(m − 1)). The gate at m 0.25 is below that line for every c ≥ 0, so it only turns non-positive corner values into −1e6. A voxel could be lost only in a cell that has a corner with m < 0.25 and another corner whose BODY is positive, which needs m > 0.475 at that corner: m would have to rise by more than 0.225 across 4 blocks, while the mask's noise has λ 700. The brief's k = 1 left BODY > 0 wherever NI > 1 + 0.35q at m = 0 (measured 9.6-17.1 % solid at y 200-250 in every column, `map-density.md` §5). Z3 records the measured loss as `gateLoss` (§5.3).
- **The band window cuts nothing.** The window evaluates BODY at the corners 192 … 264; the corners 184 and 272 and beyond hold −1e6. Every cell crossing the window's edge has corners 184/192 or 264/272; the cut changes no voxel if BODY ≤ 0 at all four, i.e. c + a·q ≥ cs at q = 0.7225 (corner 264, the smallest q of the four): 0.9 + 3·0.7225 = 3.07 ≥ 3. The corners farther out have larger q. So the window only skips NI where the term cannot be positive. Positive corners lie in 200 … 256 (at m = 1, NI must exceed 2.59 at 200 and 2.17 at 256), so island voxels lie in y 193-263, above `ISLAND_RUN_MIN_BOTTOM` (181) with a margin of 12. With the brief's a = 0.35, 35-36 % of voxels were solid at y 190 and 270, cut flat by the window (`map-density.md` §5). If c is tuned below cs − 0.7225·a (0.83), the window widens to [184, 273), which is exact while c + 1.1025·a ≥ cs (every c ≥ 0 at a = 3); island voxels then lie in y 185-271.
- **The shape.** At m = 1 a voxel is solid roughly where NI > 0.9 + 3q: for a unit-sd NI about 18 % of the points at y 230, 5 % at q = 0.25 (y 210, 250), 0.5 % at q = 0.5625 (y 200, 260); towards the cluster edge (m 0.75) NI > 1.9 + 3q, about 3 % at y 230. The review's simulation found that an offset of this size is where the core's single connected mass breaks into separate bodies (D3); how far it breaks with c = 0.9 is measured in the dry run (Z3's component extras, §5.3), and c is a lever (§1.5). The spec promises clusters of separate floating bodies, not a particular shape.
- **clampSigma.** Both arguments hold for cs ≤ 3 (the window up to cs 3.07, the gate up to cs 3.9). `density.noises.islands.clampSigma` is a slider (range [1, 8]); above 3 the window and the gate cut where NI > 3 (P ≤ 0.27 % per sample), as the leaf's doc says (§2.1). The corners 184 and 272 hold −1e6, so every voxel in y 185-191 and 265-271 blends a −1e6 corner with weight ≥ 1/8: no voxel below y 192 or above y 264 is ever solid from this term, for every slider value, which keeps island runs above `ISLAND_RUN_MIN_BOTTOM`.

### 3.5 Water v0 under islands (D5)

## 4. The islands surface branch

### 4.1 The condition (D6)

"On a floating island" = the voxel's run is vertically detached above y 180 at this position, from the data the scan already has (runTop and runBottom per run, `src/gen/surface/scan.ts:65-68`; the scan reads nothing outside its column, so lateral connection cannot be known, `scan.ts:14`):
`yAbove{minY: ISLAND_RUN_MIN_BOTTOM (181), runTop: true}` then `stoneDepth{side: 'ceiling', offset: 100, addSurfaceDepth: false}`, which hold iff runTop ≥ 181 and y − runBottom ≤ 100 (`src/gen/surface/conditions.ts:33-38`, `:45-48`).
- **One constant.** `ISLAND_RUN_MIN_BOTTOM = 181` is exported from `src/core/constants.ts`; water v0 (§3.5) and Z3 (§5.3) read it, `presetTrees.ts` builds the branch's `minY` from it, and a unit test asserts that the rules literal equals it.
- Every island voxel passes: island runs lie in y 193-263 (§3.2), so y − runBottom ≤ 70.
- A run resting on bedrock (runBottom −63, `scan.ts:67`, `:195`) never passes at runTop ≥ 181 (y − runBottom ≥ 244), so the ground, mountains included, and islands fused with a peak keep the normal palette.
- **The predicate is wider than "an island run".** It contains every island run (bottom ≥ 181), but it also passes runs whose bottom is below 181 when their top is ≥ 181 and the voxel lies within 100 blocks of the bottom: the ground's overhang lips and the floating rocks over peaks that SP3b accepted. They get the island palette (a grass top), including next to snow on cold peaks, where the default gives snow at these heights (the lapse rate, `map-surface.md` §7). Z3 and water v0 use the narrower bottom ≥ 181; Z3 records the branch's firings on runs with bottom < 181 or at islandMask = 0 (`branchFalsePositives`, §5.3), so the user sees how many peaks get grass caps. From SP6, ground over a cave whose ceiling is within 100 blocks below a voxel at runTop ≥ 181 would pass too (§12).
- **Stacked islands.** With option (a) of D21, only the first run of a position is sky-open; an island run under another island run is not, so its voxels take the band state (stone) like the ground under an island. §9's constructed-column test includes a stacked case.
